# P1.5 — Mobile shell fix (foundation before Phase 5 UI work)

> **Size:** S · **Layer:** FE · **Priority:** now (blocks building anything new mobile-first)
> **Goal:** Fix the shared app shell + worst-offender pages so new Phase 5 screens (starting
> with the P2 Kanban board) can be built mobile-first on a working foundation, instead of
> inheriting a broken one.

## Problem

Design principle #3 in `specification/08-ui-ux.md` said "mobile-first for technicians" but
was never enforced app-wide, and no page was ever actually built or audited against it. An
audit (2026-07-23) found the core app shell fundamentally broken on a phone viewport:

- `(app)/+layout.svelte` — a fixed 256px sidebar with **no responsive/collapsed state at
  all**. On a 375px phone, the sidebar alone ate 68% of the screen; there was no mobile nav
  of any kind.
- List tables (tickets, customers, inventory) wrapped in `overflow-hidden` (clips) instead
  of a scroll container — content was cut off, not scrollable.
- POS cart (`CartSidebar.svelte`) was a fixed 384px column beside the product grid — wider
  than the entire phone viewport on its own, for a screen the spec explicitly calls out as
  needing to be "touch-friendly."

## Decision

Fix the shared foundation (shell) once — it cascades to every page automatically — plus the
handful of worst, near-identical offenders (tables, POS). Do **not** attempt a full retrofit
of every existing page in one pass; that's a different, much larger, lower-leverage task.
Older pages not touched here are retrofitted incrementally as they're touched, same rule
already applied to architecture debt in this codebase (see `PHASES.md` → Architecture Debt).
New Phase 5 screens (P2 Kanban onward) are built mobile-first from the start.

## What changed

- `specification/08-ui-ux.md` — principle #3 broadened from "technicians only" to app-wide;
  added an implementation-status note explaining the audit finding and this decision; added
  a mobile-first note to the Ticket Board (Kanban) key-screen entry ahead of P2.
- `(app)/+layout.svelte` — sidebar is now an off-canvas drawer below the `md` breakpoint
  (closed by default, opens via a hamburger button in the header, closes via its own X
  button, a tap on the backdrop, or navigating anywhere), and the original always-visible
  static column from `md` up, unchanged. Added `min-w-0` on `<main>` — without it, a flex
  child can't shrink below its content's intrinsic width, which is exactly what let wide
  tables force the whole page to overflow horizontally even with a "responsive" table fix.
- `tickets/+page.svelte`, `customers/+page.svelte`, `InventoryTable.svelte` — wrapped each
  `<table>` in its own `overflow-x-auto` div (nested inside the existing rounded-corner
  `overflow-hidden` container) plus a `min-w-[…]` on the table so columns don't get crushed
  before scrolling kicks in; header rows changed to `flex-wrap` so title+button don't clip.
- POS (`pos/+page.svelte`, `ProductGrid.svelte`, `CartSidebar.svelte`) — stacks
  vertically (grid above, cart below) below `lg`, side-by-side (original behavior,
  fixed w-96 cart) from `lg` up. The toolbar wraps (`flex-wrap`) instead of clipping.
  **Real bug caught while verifying, not while coding:** the first attempt kept the mobile
  layout inside the old fixed-viewport-height, `overflow-hidden` flex column — the product
  grid's `h-[45vh]` is a flex item with default `flex-shrink: 1`, so when the now-wrapping
  (taller) toolbar left less room than 45vh, the browser shrank the grid toward zero instead
  of respecting the explicit height, and the grid silently disappeared (cart rendered
  directly under the toolbar with no product list visible at all — see 05-pos-stacked.png
  before/after in the PR). A screenshot check caught it; a bounding-box/width-only assertion
  would not have. Fixed by letting the whole page scroll naturally below `lg` (only
  bounded-height/no-scroll from `lg` up) and adding `shrink-0` to the grid so its 45vh can't
  be compressed regardless of container math.

## Verification (Definition of Done)

- New `e2e/p1.5-mobile-shell.spec.ts` (Playwright, real browser, not simulated):
  - **375×667 viewport:** sidebar starts off-screen (`-translate-x-full`); hamburger opens
    it (`translate-x-0`, nav links become visible); closes via backdrop tap (clicked at a
    point actually outside the drawer's width, not its geometric center — the center of a
    full-viewport backdrop element sits *behind* the visually-topmost drawer, which is also
    a real finding worth knowing for any future backdrop-pattern code, not just this test);
    closes via its own X button; closes automatically on navigation.
  - Tickets list: the table is wider than the viewport (proves it didn't get crushed) but
    the **page** itself never exceeds the viewport width (proves it scrolls in its own
    container instead of forcing the whole page to overflow).
  - POS: page width stays within the viewport; visually confirmed via screenshot that the
    product grid actually renders (catching the flex-shrink bug above).
  - **1280×800 viewport:** sidebar always visible, no hamburger rendered at all — desktop
    behavior is provably unchanged.
  - All 4 tests pass. Screenshots in `test-results/p1.5-mobile-shell/`.
- `npx svelte-check`: 698 files, 0 errors, 0 warnings (checked after every edit, including
  after the POS fix).
- Backend untouched — no `flowserv-api` changes, no need to re-run its test suite.

## Watch out

- The backdrop-button click-target lesson above: a `fixed inset-0` backdrop element's
  default (geometric-center) click point can be covered by a higher-z-index sibling that
  only visually occupies part of the viewport. Don't assume "click the backdrop by role"
  targets a visible point — pick an explicit position outside the overlapping element.
- Don't reach for `h-[Xvh]` + a flex parent as "the height is guaranteed" — flex-shrink
  defaults to 1 and will compress an explicit height if the container runs out of room.
  Either add `shrink-0` explicitly, or (often more robust on mobile, as done for POS here)
  stop fighting for a bounded, non-scrolling height at all and let the page scroll.
