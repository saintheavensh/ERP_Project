## 0. Temuan terverifikasi (dijalankan, bukan dibaca)

### T5 — Lubang akses finance: **BUKAN** sekadar "halaman bisa dibuka" 🔴

Pemilik menulis di C7/C8: *"anehnya kasir bisa akses halaman itu tidak hanya kasir teknisi
juga bisa akses"*. Setelah diperiksa, **keadaannya lebih buruk dari yang terlihat di layar**.

Diverifikasi live via curl (`RBAC_MODE=enforce`, DB seed bersih, login asli tiap peran):

| Endpoint | Kasir | Teknisi | Isi yang keluar |
|---|:---:|:---:|---|
| `GET /v1/finance/payables` | **200** | **200** | daftar hutang ke supplier |
| `GET /v1/finance/ledger` | **200** | **200** | seluruh buku kas |
| `GET /v1/finance/ledger/summary` | **200** | **200** | `revenue 220000, cogs 150000, estimatedProfit 70000` |
| `GET /v1/finance/receivables` | **200** | **200** | piutang |
| `GET /v1/settings/company` | 403 ✅ | — | — |
| `GET /v1/users/list` | 403 ✅ | — | — |
| `GET /v1/branches` | **200** | **200** | daftar cabang |
| `GET /v1/settings/payment-methods` | **200** | **200** | metode pembayaran |

**Jadi ini kebocoran data, bukan halaman kosong.** Kasir dan teknisi bisa membaca omzet,
modal, dan **laba toko**. Itu menabrak langsung aturan yang pemilik tulis sendiri di
kesimpulan uji R1:

> *"Kasir saja, teknisi hanya bisa melihat harga jual yang di input oleh manager"*

**Sebab yang sebenarnya — dan ini bentuk cacat yang proyek ini sudah berkali-kali temukan:**

Permission `finance.view_reports` **sudah ada** di katalog seed (`01-core.ts` baris 26) dan
**sudah diberikan ke Manager** (baris 84). Tapi:

```
grep -rn "finance.view_reports" flowserv-api/src/
  → hanya 2 hasil, KEDUANYA di db/seed/01-core.ts
  → tidak satu route pun memanggil requirePermission('finance.view_reports')
```

Izinnya didefinisikan, diberikan, lalu **tidak pernah dipasang**. Persis bentuk cacat S5
(tiga kapabilitas tahap yang ternyata tak ditegakkan di backend mana pun) dan Track F
("wired but lies"). Gerbangnya tidak jebol — gerbangnya **tidak pernah dipasang**.

**Sebab lapis kedua (frontend).** `flowserv-web/src/routes/(app)/+layout.server.ts` hanya
memeriksa `locals.user` (sudah login), **tidak pernah memeriksa peran**. Sidebar
menyembunyikan menunya (S2), tapi mengetik alamatnya langsung tetap tembus. Ini persis yang
`tahap-b-peran-dan-qc.md` baris 347 sendiri peringatkan: **"Menyembunyikan tombol bukan
keamanan."**

## 1. Pagar scope — apa yang **TIDAK** dikerjakan di R1.5

Uji R1 menghasilkan ~15 permintaan. Hanya 4 yang masuk fase ini. Sisanya **bukan ditolak**,
tapi memang rumahnya di R2/R3 — dan menyeretnya ke sini akan mengulang persis kesalahan yang
`go-live-penyederhanaan.md` ada untuk menghentikan (tiap fase menambah, tak ada yang
merapikan).

| Permintaan pemilik | Rumahnya | Alasan |
|---|---|---|
| Kasir: daftar tiket disederhanakan (progres + teknisi + catatan teknisi) | **R2** | Ini definisi R2: halaman tiket per peran |
| Kasir: riwayat tiket buatan sendiri | **R2** | Sama, butuh lapisan `ticketSectionsFor` |
| Kasir: popup pilih teknisi (bisa dilewati) | **R2** | Butuh keputusan penugasan dari R2 |
| Teknisi: ambil kerjaan 1 klik dari beranda | **R2** | Menyentuh beranda + daftar per peran |
| Teknisi: tidak ada dropdown "pilih teknisi", ganti "request pindah" | **R2** | Tepat isi T3/R2, + butuh endpoint baru |
| Teknisi: tidak boleh lihat harga modal | **R2** | Bagian `ChargesSection` per peran |
| Teknisi: laporan bulanan (selesai/komplain/gagal/dikerjakan) | **R2.5 / baru** | Fitur baru, butuh query agregat |
| Kanban: tiap tahap wajib isi field tertentu | **R3+** | Aturan per tahap — dekat ke QC, bukan tampilan |
| Input biaya digabung (total + sparepart, lihat katalog) | **R2.5 / baru** | Mengubah alur biaya, bukan render |

**Aturan tetap:** satu fase = satu commit atau lebih, tidak pernah menggabung dua fase.

## 2. Task

### Task R1.5A — Tutup lubang finance 🔴 (backend dulu, baru frontend)

- [ ] **Backend, ini gerbang yang sebenarnya.** Pasang
      `requirePermission('finance.view_reports')` pada seluruh GET di
      `routes/finance.ts`: `/payables`, `/payables/:id`, `/receivables`, `/ledger`,
      `/ledger/summary`, `/ledger/reconcile`
- [ ] Verifikasi live: kasir & teknisi → **403**, Manager & Super Admin → **200**
- [ ] **Frontend, ini kenyamanan bukan keamanan.** `(app)/+layout.server.ts` (atau
      `+page.server.ts` per rute) menolak peran yang tak berizin dengan **redirect ke `/`
      + pesan**, bukan halaman kosong yang menyesatkan

**⚠️ Perhatian ekstra:**
- **Jangan bikin permission baru.** `finance.view_reports` sudah ada, sudah di katalog, sudah
  diberikan ke Manager. Menambah kode baru berarti dua sumber kebenaran untuk hal yang sama.
- Karena izinnya sudah ter-seed, task ini **tidak butuh `db:reset`** — hanya kode route.
  Ini sengaja: perbaikan keamanan tidak boleh bergantung pada data lokal dihapus.
- `GET /branches` dan `GET /settings/payment-methods` **sengaja dibiarkan terbuka** — POS
  kasir memang membutuhkan keduanya untuk bekerja. Yang bocor bukan itu; yang bocor angka
  uang. Jangan ikut menutupnya lalu merusak POS.
- Halaman `/finance/ledger`, `/finance/payables`, `/finance/receivables` punya
  `+page.server.ts` masing-masing — jangan hanya menutup `/finance`.

### Task R1.5B — Cabut `ticket.create` dari Teknisi

- [ ] Hapus `'ticket.create'` dari `ROLE_PERMISSION_CODES[IDS.roleTechnician]`
- [ ] Hapus baris menu pembuatan tiket dari sidebar Teknisi bila ada
- [ ] `npm run db:reset` (grant berubah → wajib reset, bukan `db:seed`)
- [ ] Verifikasi live: teknisi `POST /v1/tickets/intake` → **403**; kasir tetap **201**

**⚠️ Perhatian ekstra:**
- Teknisi **tetap** butuh `ticket.diagnose` (untuk klaim pekerjaan lewat
  `POST /:id/claim`) dan `ticket.manage_charges`. Cabut **hanya** `ticket.create`.
  Salah cabut = teknisi tak bisa ambil kerjaan lagi, dan itu tepat bug yang R1 baru saja
  perbaiki.

### Task R1.5C — Validasi sandi/pola minimal 4

- [ ] Zod di backend: sandi/pola, bila diisi, minimal 4 karakter/titik
- [ ] Frontend: pesan galat yang terbaca, bukan hanya tombol mati
- [ ] Tetap **boleh kosong** — tidak semua unit punya sandi

**⚠️ Perhatian ekstra:**
- Validasi wajib di **backend**, bukan hanya form. Ini pelajaran berulang proyek ini
  (S5: "kuncinya semu; satu panggilan API langsung menembusnya").

### Task R1.5D — Kasir tidak dilempar ke halaman detail

- [ ] Setelah simpan intake, kasir **tetap di halaman intake**, muncul toast
      *"Tiket <nomor> berhasil dibuat"*
- [ ] Peran lain: perilaku lama tidak berubah

**⚠️ Perhatian ekstra:**
- Pemilik (A9): *"jangan langsung ke halaman detail buat saja toast notifikasi"*. Alasannya
  operasional — kasir menerima unit berturut-turut saat toko ramai; tiap kali dilempar ke
  detail berarti harus menekan "kembali" sebelum bisa melayani orang berikutnya.
- Nomor tiket **harus** ada di toast. Tanpa itu kasir kehilangan satu-satunya pegangan untuk
  menempel di unit.

### Task R1.5E — Tes

- [ ] Playwright `r1-5-akses-finance.spec.ts`: kasir & teknisi buka `/finance` dan
      `/finance/ledger` → **tidak melihat angka uang** (assert tidak ada di DOM, bukan
      sekadar tak terlihat); Manager → melihat
- [ ] Playwright: teknisi tidak punya jalan membuat tiket
- [ ] Playwright: kasir simpan intake → toast muncul, alamat **tetap** di intake
- [ ] Jalankan ulang: `r1-peran-akses`, `p3-role-dashboards`, `p5-finance-dashboard`,
      `intake-to-close`

**Definition of Done R1.5:**
`npx vitest run` hijau · `svelte-check` 0 error · spec baru + spec lama lulus ·
verifikasi curl 403/200 terekam · **uji manual pemilik** (`uji-R1.5-*.md`)
